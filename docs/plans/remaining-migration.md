## 目标与完成定义

一次性完成当前仓库剩余的命名、独立性、目录、文档、验证与提交收尾。交付一个可以继续开发、按作品独立导出且能识别真实成熟度的仓库。迁移完成不等于所有存量作品成为 stable，也不等于已经公开发布或所有宿主都已实测。

已经完成的一级目录迁移、数据归档和基础检查修复不重复实施。已有本地提交 `92ed87b`、`3d99f7f` 保留；未提交的会议纪要独立验证结果纳入本轮。

- 包含以下作品及其调用方、脚手架、导出器、测试、仓库入口和发布说明。

- 不新增完整的缺失业务运行时、不改业务口径、不改写 Git 历史。许可证来源未明确的作品保持 draft 和不可正式发布，不自动授予 MIT。
- 不推送、不合并、不创建公开发行、不替换全局安装。不使用真实业务数据执行外部上传、创建待办或发送消息。

## 执行顺序

### 1. 固定现场与核对依赖

检查分支、worktree、暂存区及已有修改，记录保护文件哈希。遍历每个范围内作品的 README、SKILL、脚本、清单和调用方，列出绝对路径、跨目录依赖、缺失资源、当前运行限制和许可证来源。以代码及测试确认实际输入输出，不照搬历史宣称。

### 2. 先消除跨目录依赖

- 优先处理 create-report：将生成模板和资源放在作品自身目录，去掉对仓库根目录的隐式依赖。使用 Python 提供 Windows/macOS 可直接调用的入口，Bash 仅保留可选兼容包装；原参数有真实调用方时保留其语义。
- 对各报告 Skill：将执行所需需求与合同放回各自 references/assets，修正作者路径和跨目录读取；共享样式只有真实依赖时才随包携带。保持新旧交易生成器合同分离。
- 对 skill-health：明确通用本地检查与 Hermes 用量接入的可选边界，缺少可选环境时清晰降级，不能伪造使用数据。
- 对 skill-quality-review：整理实际指令、引用和清单；对 circle-content-analyzer 保留协议层 draft，明确没有正式运行脚本。
- 对 wxurl2md：复核包内依赖、配置、专用浏览器 Profile 和失败退出；保留已完成的离线能力，不主动进入真实账号操作。

实现修改仅围绕独立运行与迁移必要性，不附带重构业务算法。

### 3. 统一改名与入口

按映射迁移九个目录，随后一次同步代码引用、元数据、工具测试、目录说明及 .gitignore。检查旧路径残留，将合法历史提及与错误运行依赖区别处理。不修改保护目录来迎合新名称；如保护目录依赖旧路径，则采用不干扰其实现的兼容方案或保留该项暂缓理由。

### 4. 整理每个作品的交付合同

README 说明用途、输入输出、依赖、配置、最小运行示例和当前限制；SKILL 保留 Agent 的准确触发与工作流，遵守 skill-creator。版本和状态以已有事实为依据，不批量升级为 stable。兼容矩阵区分已验证、未实测与不支持；Bash 依赖不写成 Windows 原生支持。

逐项列出许可证与第三方材料来源。能确认的保留其许可；不能确认的明确待确认，允许开发草案导出，发布检查继续拒绝，不通过虚构 LICENSE 获取绿灯。未完成真实运行时的作品不宣称独立可执行。

### 5. 验证与修复

- 全仓基础 lint、样板发布 lint、涉及 Skill 的 skill-creator quick_validate。
- 脚手架和导出器的行为测试，重点验证新名称、包内资源及过滤后的包。
- 所有有运行时的迁移作品在仓库外临时目录进行草案导出，运行对应合成数据测试；检查不依赖父仓库、根 node_modules 或作者绝对路径。缺失测试时只补能验证实际行为的最小案例。
- 报告保留已知数值和结构断言，不仅检查 HTML 文件存在；运行时代码未改变的部分不无故重复扩测。
- 会议纪要保留已完成的 Luna 独立验证证据；其他复杂指令只在有实际疑点时用独立 Luna 验证，不为每个目录机械委派。
- 浏览器插件运行现有三项离线回归。真实登录抓取、目录授权及账号操作不作为本轮自动测试。
- 提供适合 Windows/macOS 的测试命令；当前没有 Windows 执行环境时记录未实测，不将静态兼容审阅冒充实测。

### 6. 统一收尾与本地提交

更新根 README、作品目录、规范、名称映射和最终验收报告。核验本地数据仍被忽略、归档仍存在，保护文件哈希不变，所有本轮临时文件清理完成。执行 git diff --check，审阅暂存区，按合理阶段创建仅含本任务文件的本地提交。

最终统一汇报：迁移作品清单、实际运行的检查、提交编号、未决许可和实测范围。保留其他任务的未提交改动，暂存区清空，不推送。

## 验收标准

1. 九个可迁移目录完成映射，开发中例外有明确记录；当前使用入口无失效旧路径。
2. 模板、脚手架、导出和调用方使用一致的名称与参数。
3. 有运行时的作品能在独立目录执行合成回归；纯指令或协议草案准确声明能力，不编造实现。
4. 结构检查、对应定向测试、包内资源检查及差异检查通过。若发现原有运行时失败，修复迁移引入的问题；超出迁移范围的既有业务问题需明确记录，不能静默称全部通过。
5. 许可未确认、真实账号流程、Windows 与其他宿主未实测，逐项可见，不妨碍完成仓库迁移，但仍阻止对应正式发布宣称。
6. 所有本轮工作形成可审阅的本地提交，其他任务文件与用户全局安装不变。

## 一次确认后的执行授权

确认本计划即授权上述范围内的代码、文件移动、文档、必要测试、临时独立包验证及本地 Git 提交；执行中自主解决一般选择与可逆修复，不逐步请求确认。缺少可选环境或额度时继续其余工作，记录验证边界。

仅在发生以下情况时停下相关步骤并集中说明：用户保护文件发生无法安全整合的冲突；存在必须由用户确认的权属或业务口径且无法以 draft 隔离；执行需要计划外的外部写入、费用或不可逆操作；平台权限实际拒绝且没有合规替代。权限工具自身的审核由平台控制，用户对计划的确认不能取消平台约束。
