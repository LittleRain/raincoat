# 品牌信息源

按品牌记录「新盘从哪来、价格在哪、赏品构成在哪」，避免每次重新试错。表里的「状态」只有三种：`已验证`（本工作流实际跑通）、`候选`（账号/页面存在但没验证过内容）、`无`（公开渠道拿不到，需人工）。

## 使用与迭代规则（本文件是唯一真源）

- **开跑前必读**：`new-lineup-by-brand` 和 `lineup-subitems` 的第一步都是读本文件。不要跳过，也不要把品牌源另抄到别处。
- **收尾必回写**：每跑完一轮，按下面清单更新本文件，再交付。没回写等于这次白学。
  - 新品牌 → 在「国内抽赏品牌」表加一行，状态按实际观察填 `已验证 / 候选 / 无`。
  - 状态升级（`候选`→`已验证`，或 `无`→`候选`）→ 改状态，并在「已验证的经验」补一句是怎么拿到的。
  - 新坑（搜索漏帖、同名盘、砍赏、抽数异常）→ 写进「已验证的经验」，一条一句话，可复现。
  - **官方渠道迭代（每轮必做）**：本轮新发现的官方号/公众号/小红书/官网 → 加进「官方信息渠道」表；发现停更、改名、迁移 → 标 `失效`；发现某渠道**只发预热不发构成** → 在「发什么」列写清，避免下次又去那儿等结构。日志里记一句「本轮从哪个渠道拿到的」。
  - 新增日方站 → 先加到追踪表「品牌信息」子表（`q979lj`），这里只写一句指回去。
- **不写推测**：没验证过的账号只能标 `候选`，不能写成 `已验证`；价格和构成拿不到就写 `无` 并注明实际渠道。
- **表格自检**：四个数据列齐全、品牌名不重复、每行的状态只能是那三个值。

## 抓取优先级（2026-10-23 定稿：两阶段，双 Agent，批量调用）

### 阶段 1 · 发现窗口内的新盘（**全部品牌一次调用**）

把窗口内全部登记品牌写成一份清单，**同一个 prompt 一次性**分别发给 workbuddy 和 bitto（不要一品牌一次）：

> 本轮窗口 <since> ~ <today>。请逐个品牌查：这段时间发售了哪些赏盘？
> 品牌：<全部登记品牌>
> 输出：每个品牌一行 —— 品牌 | 盘名 | 发售日 | 单抽价 | 来源渠道；没有新盘的品牌写「无」。

- 回来后做**完整性矩阵**（品牌数 × 2），要求每个品牌都有返回（含「无」）；漏掉的品牌单独补问，每 Agent 最多 1 轮。
- 某个 Agent 整体失败 → 重试 1 次，仍失败就只用另一方结果并注明。
- 合并：并集、按「商品名称」归一化去重、标 `wb`/`bitto`/`both`；同名但日期或价格冲突 → 官方渠道核实，核实不了不写。
- 两边都报「无」的品牌 → 按官方渠道复核一轮，翻完也没有才记「本轮无新增」。
- 阶段 1 只出候选清单，不写表。

### 阶段 2 · 按盘补基础信息与子品（**分批**，workbuddy → bitto → 官方渠道）

候选盘按 3–5 盘一批发给 workbuddy，逐盘要「单抽价 / 整套抽数 / 每个赏各几个」：

1. 先 workbuddy 跑整批
2. 某盘缺任一项 → 只针对该盘问 bitto，不重跑整批
3. 仍缺 → 按「官方信息渠道（按品牌）」表走官方号/公众号/海报/官网 → 官方小程序/天猫详情
4. 都没有 → 标缺源

- **缺一项即算失败**，不允许部分写入；冲突以能通过 `Σ(各赏，不含 LAST) == 整套抽数` 的一方为准，都过但冲突走官方渠道裁决。
- **二手渠道只能确认「有没有发售、哪天发售」**，价格与子品结构不采信、不写表、不反推。

## 已验证的经验（少走弯路）

- **搜索会漏帖**：`龙珠 THE CHRONICLE OF GOKU`、`Harry Potter Magical Holiday`、`东方Project`、`进击的巨人`、`航海王 红发海盗团` 在微博搜索里都搜不到官方帖，翻 `万代南梦宫潮玩` 时间线（30 页 ≈ 300 条）才全部找到。
- **同名不同盘**：`Harry Potter Magical Holiday` 与 `Harry Potter Magical Sweets Party` 是两套盘，赏品完全不同。按 IP 名匹配会抓错，必须用完整系列名。
- **官方号会发多套同 IP 的盘**，时间线里连续出现，取帖子时要看「正式发售」那句里的系列名。
- **一番赏ONLINE 独有盘**（史迪奇、奥特曼 60 周年、宝可梦 30 周年 vol.2、链锯人蕾塞篇第 2 弹）的价格不在微博、也不在公开商品页，在「一番赏ONLINE」微信公众号发售推文正文里。
- **卡游「预约」不是发售**：2026-10-21 变形金刚 KAYOU赏第 1 弹只有「预约得明信片」（10-21~10-25）与「即将上线」，截至 10-26 无「正式上线」帖，按口径不进表。判断卡游新盘只看有没有 `正式上线` 字样的帖。
- **会员购商品池/商家池/分销/混池不作为新盘来源**（2026-10-26 定）：这些池子是转售与混装，盘名和价格都不稳定；自营店挂牌只当「可能已发售」的线索，价格与构成仍要官图。Bitto 阶段 1 曾据以报出 177 个「磁力赏新盘」，全部是平台池，不进表。
- **B站商家池上架 ≠ 品牌官方发售**：会员购里 万画赏/福赏/另物赏/好物赏 多由第三方商家池承载，上架时间和价格只能当「可能已发售」的线索，不能当价格或结构来源；要写表仍需品牌官方渠道确认。
- **两个 Agent 分工（2026-10-26 实测）**：子品结构与日文赏名**主查 workbuddy**——它一次就给出了 6 套盘的全部赏名，其中 3 套还带「共N个」逐赏数量；Bitto 只适合补核与总抽数交叉。Bitto 这轮卡在搜索引擎（Bing 302、DuckDuckGo 返回无关词条），不要让它单独承担阶段 2 主查。
- **`local-agent` 提交的两个环境坑**（2026-10-30 实测）：① `local-agent submit bitto` 在 workspace-write 文件策略下会因 `~/.local/state/bitto-agent-bridge/jobs` 不可写而失败，需放宽到 danger-full-access；② `local-agent submit workbuddy` 报 `No such file or directory: ~/.workbuddy/cache/acc-product-config-v3.json`，把最新的 `acc-product-config-v3-<pid>-<uuid>.json` 复制成该文件名即可提交。
- **MCP 工具可能整体消失**：会话里 `mcp__local_agents__*` 不在工具列表时，改走 `local-agent submit/get/wait` CLI（wait 上限 50 秒），其余流程不变。
- **国内品牌没有统一官图规范**：磁力赏/英雄赏等的价格与构成分散在各自小程序里，别在微博上反复试。
- **`ocr_post.py` 不能并发**：切片临时文件写死为 `/tmp/ocr_{i}_{j}.jpg`，多盘同时跑会串图（实测哥斯拉盘的 OCR 里混进史莱姆盘）。多盘必须串行，或先把脚本改成按盘分临时文件。
- **已下载的图不会重下**：脚本对「存在且 >10 字节」的图直接复用，`curl` 截断的 jpg 会让 PIL 抛 truncated —— 遇到就删掉该图重跑。
- **代理版官图多用中文品名**（如「罗小黑毛绒玩偶」「小黑猫坐垫」），子品名称按官图原样写即可，不必翻成日文；只有官图给日文名时才保留日文。
- **定位帖子别只靠下标或关键词**：时间线第 59 条实际是 POTEPOTTE 六周年帖，不是罗小黑；同名系列还可能有两帖（225 是实物照片、227 才是构成官图）。用「正文系列名 + 官图标题」双匹配。
- **国产品牌官微活跃度差到不能用同一套办法**：磁力赏官微停更于 2025-01-25、福赏停更于 2025-12-31、分子互动停更于 2022-09，这三个品牌表里的新盘（小鹦鹉BEBE 7-24、火影少年篇 7-22）在微博上没有任何证据，只能去渠道取。
- **好物赏是国产品牌里唯一能靠官微覆盖的**：`阅文好物`（uid `6610662664`）8 个月连发 9 套，帖文给系列名 + 开售日，但不给价格、也没有「共N个」。
- **卡游主号时间线只回溯到约 2026-04-22**（约 50 页上限），要更早的用 `卡游潮玩`（覆盖到 2026-02）交叉补位。
- **同日「即将上线」与「正式上线」并存**：卡游系三个号常不同步，判断以写「正式上线」的那个号为准（银魂 9-30 案例）。
- **乐淘谷/阅文好物的新品帖用 `⏰：M月D日` 标排期**，日期没到就不是已发售（暹罗厘普 ⏰11月13日）。

- **B站会员购数仓已停用**（2026-10-23）：`bi_mall.dim_ichiban_*` 里的配比大多是商家自组盘/复刻盘的，不等于官方赏配置，曾据此填过一批结构。**不要再拿它当结构源**，也不要拿它反推官方抽数。

## 新增品牌怎么补这张表

1. 微博用户搜索接口 `containerid=100103type%3D3%26q%3D<品牌>`，取粉丝量最高且带 V 的账号。
