# 0.3.0：按结构生成，不再堆场景长文案

需求真源：[product-v0.3.md](../product-v0.3.md)。这版把生成器从「按场景追加长文案」换成「六槽位 + 模型档位 + 纯文本渲染 + 最多 3 个阻塞追问」。

## 行为变化

| 项目 | 0.2.x | 0.3.0 |
| --- | --- | --- |
| 生成方式 | 场景模板 + 规则追加 | 六槽位骨架（角色/目标/材料与约束/衡量方式/边界/输出形态） |
| 长度 | 越长越「专业」 | 按模型档位封顶：前沿 ≤4 句/≤120 字、中档 ≤7 句/≤220 字、受限 ≤10 句/≤320 字（**只算新增句**，用户原话不截断） |
| 标记 | 可能带分节/列表 | 纯文本段落，无 `#`、`**`、`<tag>`、编号 |
| 缺信息 | 往里补占位符 | 只对阻塞槽位最多问 3 个（带默认值），非阻塞缺失不写进 prompt |
| 模型差异 | 一条 WorkBuddy 工具规则 | 5 份 profile：gpt / claude / bitto / workbuddy / deepseek，各自 tier、预算、顺序、官方出处 |
| 评测 | A–E 双评委盲评门禁 | 结构回归（槽位/预算/无标记/无占位/无编造数字/两次一致/追问≤3），360 次本地渲染 |

## 新增与删除

- 新增 `Sources/PromptCore/SlotComposer.swift`、`Resources/model-profiles.json`、`Resources/scene-slots.json`、`scripts/eval/structure_check.py`。
- `AgentTarget` 增加 `claude`、`deepseek`；窗口识别支持 Claude 桌面端 bundle。
- 浮窗改为调用 `SlotComposer`，预览上方显示「profile · 场景 · 补充 N 句 · 待补充：X（已用默认）」。
- 移除：A–E 盲评门禁和证据通道（`judge.py`、`run_judge.py`、`harness_*`、`tools_*`、`run.py` 等）移入 `scripts/eval/legacy/`，不再被 `test.sh` 与构建调用。
- 删除：`prompt-rules.json`（场景长文案与规则）、`RuleCatalog.swift`、`PromptComposer`/`PromptDraft`/`Scene`、`validate_rules.py`，以及 `--compose`/`--eval-compose`/候选目录等旧 CLI 分支。Swift 测试整体重写为 v0.3 结构测试（13 项）。

## 官方依据

- OpenAI：reasoning model 像资深同事（给目标即可），GPT 模型像初级同事（需明确指令）—— https://developers.openai.com/api/docs/guides/prompt-engineering
- Anthropic：迁移章节明确 **Remove over-prompting** —— https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices
- DeepSeek / Kimi：未找到官方结构指南（`api-docs.deepseek.com/guides/prompt_engineering` 返回 404），profile 标 `official: false`，按模型类别归档。

## 验证

```sh
bash scripts/build-app.sh          # 构建 + 数据门禁
bash scripts/test.sh               # 60 题校验、结构回归 360 次渲染、21 Swift 测试
```

手测：先退出旧进程，再打开 `dist/Raincoat Prompt.app`。输入「帮我加个重试机制」，目标选 WorkBuddy → 预览应是一段纯文本，含「你是后端工程师…」与「你没有工具执行能力…」；切到 Claude → 不应出现角色句，且补充句不超过 4 句。

## 已知缺口

- 浮窗只**展示**待补充项与默认值，还不能逐项改填（0.3.1）。

- 场景判定是关键词启发式，长输入可能误判；结构回归只覆盖题库 60 条。
