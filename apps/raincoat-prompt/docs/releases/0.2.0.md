[预注册](../../.build/evaluation/stage7-preregistration.md)已声明用户摘要是已知信息；不是完全未知结果的前瞻实验。两个评委各看匿名交换顺序，只有双顺序同向才计胜负。

| 对照 | Bitto评委：胜–平–负 / 一致 | WorkBuddy评委：胜–平–负 / 一致 |
| --- | --- | --- |
| 主集C''/A | 17–5–5 / 23/27（85.2%） | 17–5–5 / 23/27（85.2%） |
| 既有holdout回放C''/A | 4–2–2 / 6/8（75%） | 4–2–2 / 6/8（75%） |

两个评委均主集胜多于负、顺序一致率至少75%、既有保留回放胜不少于负。holdout与既有保留是同一批8对，不能双算为两个独立泛化样本；未见新holdout仍未覆盖。

无新增关键错误单独核验：Bitto空闲后端对全部35对做两个顺序的结构化错误审计，沿用原critical_errors，未检出候选相对A的新增关键错误。此前WorkBuddy采购题“整体6周交付”非盲初评被两个匿名顺序均判为未触发工期关键错误；原分保留，新核验单列，不覆写历史。这项审计仅用一个空闲评委，不冒充两评委都做了独立错误清单。

## 残留风险与验证范围

顺序一致不能保证评委正确；同模型评自己的历史回答、短reason及同源训练可能带来偏差。导入旧盲评未记录实际型号回显、完整usage或job，不把请求标签当供应商确证。只有新增结构化审计保留了完整原始状态、型号与token。

35对是固定材料任务，不能代表真实联网、SQL、代码实现和所有harness。C''/C'仍有不少败例，不能称0.2.0对每道题都更好；发布遵循预注册总体净收益与无新增关键错误，而非临时要求逐对不败。验收包括统一测试、codesign、随包资源及CLI/浮窗共用生成器核对。用户原PID77180不重启，未声称已把运行中的旧GUI替换为新进程。
