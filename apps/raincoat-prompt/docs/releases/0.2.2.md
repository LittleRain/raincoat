## 重启后才会生效

构建覆盖了主路径 `dist/Raincoat Prompt.app`，但没有退出或重启正在运行的旧进程 77180；运行中的进程不会自动换用新二进制。请先由用户从菜单栏选择“退出 Raincoat Prompt”，再执行：

```sh
cd /Users/raincai/Documents/GitHub/raincoat/apps/raincoat-prompt
/usr/libexec/PlistBuddy -c 'Print :CFBundleShortVersionString' 'dist/Raincoat Prompt.app/Contents/Info.plist'
open 'dist/Raincoat Prompt.app'
```

第一条检查应输出 `0.2.2`。旧进程未退出时，仅执行 `open` 会激活原进程，不能验证新版本；本轮不会代用户退出。原 0.2.1 app 已备份到 `.build/rebuild-0.2.2/baseline/Raincoat Prompt.app`，旧 CLI 输出与清单也已保留。

工具边界规则只反映当前 WorkBuddy 桥接的已测能力，后端升级后需重测；此次重建不会消除该已有风险。源码重新构建仍需要清单引用的本地评测证据与旧 catalog 快照，分发 app 本身不读取这些 `.build` 工件。

## 用户手测（先按上文退出旧进程、打开 0.2.2）

1. 按已配置的唤起快捷键（默认 `⌃⌥Space`）→ 出现输入浮窗 → 无响应说明快捷键注册或唤起链路异常。
2. 场景选“自动”，依次输入“帮我加个重试机制”和“调研一下竞品定价”并各停顿约半秒 → 标签分别显示“自动 · 开发”和“自动 · 调研” → 不符说明场景识别或自动刷新回归。
3. 目标选 WorkBuddy、模型选 `kimi-k2.5`，输入“帮我加个重试机制”并按 `⌘↵` → 预览含“硬性要求：你没有任何工具或文件读取能力” → 缺失说明开发适配或规则资源加载异常。
4. 每次先点“返回修改”，分别在 Bitto 下用同一开发输入生成、在 WorkBuddy 下用“调研一下竞品定价”生成 → 两份预览都不含上述工具边界段 → 出现说明目标或场景作用域外溢。
5. 在预览按 `⌘↵`（复制并关闭）后粘贴到空白文本编辑器 → 浮窗收起且粘贴内容与预览一致 → 不符说明剪贴板或窗口状态切换异常。
6. 重新唤起并回到编辑态，打开“唤起设置…”，录入不冲突的新组合并保存，再用新组合唤起并恢复原设置 → 保存成功后新组合可唤起 → 不符说明快捷键保存、注销或重新注册异常。
