# 评测协议与历史对账

## 当前协议

从第7阶段起，人工初评用于筛查问题、校准rubric和确定需要复核的原文，不单独决定发布。发布使用预先登记的匿名机器评审：同一原稿、材料和rubric，两份原始回答隐藏版本、目标、型号与运行ID；两个评委分别看两个交换顺序。第二顺序先映射回原回答身份；两次同向才计胜/负，否则记平。两次tie是一致的平。解析失败、调用失败或缺失顺序属于未完成，不伪装成平局。

顺序一致率为两个顺序映射后相同结果的有效配对数/双顺序均有效配对数；它衡量位置敏感性，不能证明评委判断正确。两个评委也不是两名独立真人；同模型可能评自己的历史回答，版本匿名不等于统计独立。不同评委分别报数，不只挑有利评委，也不将重复评委票当成新的答题样本。

关键错误沿用题目原清单。胜负、简短reason都不能自动证明“无新增关键错误”；有疑点须回到原文，记录编号与逐字引用。结构化critical通道分别列A/B错误；交换顺序后比较“候选错误集合减基线错误集合”。基线自身错误有分歧、但候选两次均无错时，不据此制造候选新增错误；新增集合不同则标不确定，不伪装通过。建议、条件和目标不自动等于已实现保证，必须读整段限定语。

每轮在读取新结果前保存`.build/evaluation/stageN-preregistration.md`，写明题集、版本与规则快照、评委/模型、顺序算法、预算、有效配对、错误处理和发布条件。已知结果必须声明，不能追称完全前瞻预注册。新门槛只能在预注册后对新实验生效；不得看完结果后增删条件，也不得换题、换评委或删除负例凑发布。

## 人工初评与盲评差异

第5阶段plan规则人工初评为4胜2平2负。导入时核验完整文件的8个唯一配对/评委，按E胜–平–负统计，Bitto为2–1–5、WorkBuddy为3–2–3；合计5–3–8。消息摘要中的“2–5–2”与8对范围不一致，因此保留摘要为背景，报告使用带行哈希的完整文件，不反向修改结果。

差异集中在：人工初评如何理解复合核心项、是否把隐含动作视为完整验证、对“预计”跨段语义的严格程度，以及额外错误是否属于预定关键错误。盲评也可能漏项、混淆目标和保证，不能仅因匿名就视作真值。第7阶段将工期争议单列结构化复核，原评分保留，纠正有独立记录与原句，不覆写历史。

人工初评只筛查的规定不意味着废弃人工事实核对；它意味着发布不能只依赖执行模型看着版本与映射打出的分数。后续应保留固定校准样本、评委分歧、顺序不一致和所有失败。模型/Agent规则启用还须满足其已登记的结构、型号与相邻单规则证据约束；现有适配校验器不自动消费机器盲评，未接通所需证据前不得用人工分数单独启用新规则。

## 迁移与复现边界

旧`/tmp/blindjudge`脚本会重试提交，并把JSON解析失败映射到0；新通道不沿用这两种行为。旧文件按完整行只读快照导入，校验顺序与winner映射，保留原始行哈希、截断reason与格式兼容标记；旧脚本没保留的job、耗时、tokens和observed_model仍为null，不补造。额外JSON字段或前置分析只作迁移兼容，新调用必须完整输出符合schema的JSON。

新调用通过`local-agent submit`一次创建job，以同一job轮询wait（每次不超过50秒），不把wait轮询计为新模型调用。失败与缺失不自动重试、不覆盖原记录；总预算按提交预约台账计算。原始回答从既有runs读取，永不重新生成。匿名包与private mapping分开保存，实际评委只收到匿名包内容。

## 第8阶段harness分层协议

用户明确注册D/C双评委各净胜>0、顺序一致≥75%、复次及未见保留、无新增关键错误。因此新增stage8-harness-blind-v1适配证据通道：harness_release.py按该口径与原始target/scene/观察型号/精确单规则差异验证，evidence绑定run_dir/pair_id/run_ids/judge_dir/protocol_file。旧人工适配分数的逐对不败检查仍保留给legacy/model路径，不把它加回本轮harness盲评。

完整64格计划用相同C共享与不匹配target的D无操作控制去重；无操作只校验提示词相同，标skipped_noop，不伪造回答、不计收益。有效规则证据只来自匹配target的8个D/C配对；两个环境计划并未减少，但不能将跨环境无操作项当作新效应样本。

在48提交预算内，批量4配对/job联合判总体质量与结构化错误，仍逐题使用原rubric、同一配对两种顺序；pair/critical两条归一记录共享同job。批量可能带来题间干扰，不能将记录数当独立模型调用或样本。任何批格式失败都原样保存、不算平、不重试。传输提示ID前缀修正另留实际prompt与勘误，不能改rubric去让规则通过。

本轮固定材料指令禁止工具，因此只测试权限边界描述、建议路径与不假称已执行；不证明Bitto全局只读或WorkBuddy真实写文件能力。发布门槛是探索性观察净胜，不是10个百分点效应的统计显著性检验；样本量另报告，不在看结果后新增为门槛。

## 第9阶段：授权的传输修复与有限重试

第9阶段明确授权仅补第8阶段缺失评审。保留全部旧失败，复用全部36个成功的有序评审，不从失败原文选择性重解析，不重生成答题。原stage8-preregistration与发布阈值保持字节不变；新传输格式和重试处理在新调用前另行登记stage9-preregistration。不是重做一次全新盲评，已知旧结果必须披露。

新通道批量2对、timeout240秒、精确ID列表/逐项四字段模板；仅ID唯一匹配时容忍前后说明，缺字段不补默认，重复不挑一条。critical_flags仍含原错误编号与逐字引文，投影到既有critical schema后使用同一critical_findings。逐项校验可保留合法项，失败不算平，不能以reason或未返回错误字段当作无错。

此前“不自动重试”在本轮有明确授权例外：只对后端超时与网关错误重试一次。失败、retry_of、raw、job、tokens与耗时均保留；现有成功评审不变。schema/缺字段/重复/型号/权限错误不重试。报告同时列首轮失败率、含重试失败率、逐项失败率和最终缺失；批大小/超时和失败子集均改变，前后故障率不构成随机对照。

新旧有效评审合并后按原门槛全量判定；不得挑有效胜例或更换rubric、评委、题集。当前judges投影的唯一记录与所有历史尝试分开存储，避免重复投票并保留失败率。批量干扰、同模型评自己历史回答、reason不等于事实、固定材料不能证明真实落盘等限制继续有效。

## 一条命令的回归入口

`bash scripts/regression.sh` 依次执行：题库校验 → 规则证据门禁 → 发布清单校验 → Python 与 Swift 测试（`scripts/test.sh` 已包含前三项），再从磁盘上最新的 `runs.jsonl` 所在目录重生成评测报告，并在有 `judges.jsonl` 的兄弟目录上重生成盲评报告。它**不发起任何新模型调用**，因此可以在任何时刻重复执行；需要新增配对时用 `run.py`（答题）与 `run_judge.py`（盲评），两者都会把预算写进各自的 `attempts.jsonl`。

## Stage11 独立确认

Stage11 是 Stage7 发布之后的第二次独立复跑，重新生成 C/A 回答，覆盖20个独立配对；它既不是复用 Stage7 原答复的再评分，也不是将两个评委或两个顺序加倍为新的独立样本。Bitto结果9胜6平5负，一致15/20=75%；WorkBuddy结果9胜4平7负，一致17/20=85%。其中12对holdout分别为6-4-2与5-3-4。结果与Stage7净收益方向一致，效应大小和评委分歧仍须分别报告。

该轮16个批量关键错误审计被中断，有效完成0/16；原始报告仍显示未完成，不得将空错误清单、缺失输出或质量胜负当作“没有新增关键错误”。Stage11因此只完成独立质量确认，没有完成又一次全套发布门禁；0.2.0场景仍以Stage7封存证据为依据。

0.2.2属于rebuild-only补丁，复用0.2.1工具面harness证据，启用规则仍仅workbuddy-no-tools；不借Stage11部分结果改变场景、规则或门禁。新清单绑定父发布清单、原规则catalog及继承证据的哈希，并验证除顶层版本外规则数据逐字段相同。
