> 交接日期：2026-10-14（Asia/Shanghai）  
> 用途：交给本地 Codex，检查现有项目后继续实施本地足球高光工作台。  
> 状态：本文是需求与实施建议，不是已有功能或模型效果的验证报告。P0 是否存在、完成到什么程度，必须现场核查。

## 1. 项目背景与已知事实

用户希望每周将孩子足球训练的 GoPro 与 iPhone 视频导入本地工作台：系统推荐精彩事件，用户确认人物、审核与调整片段、选择剪辑效果，最终生成可发布的 MP4 集锦。工作台运行在 Mac mini，电脑浏览器使用为第一优先级，手机通过局域网访问为后续能力。

用户的真实拍摄场景：

- **GoPro**：4K、全场远景，单次约 30–40 分钟。孩子和球可能很小，存在遮挡、多人相似服装、镜头畸变和远距离动作不清楚的问题。
- **iPhone**：若干较长的关注片段，可能更靠近孩子，但并非每段、每秒都是高光。必须完整扫描，不能直接把整个文件当成精彩片段。
- 两设备的录制开始时间、时钟、帧率和声音可能不同；iPhone 片段不一定连续覆盖整堂课。
- 重点事件：**进球、射门、突破、抢断**。目标人物是用户指定的孩子，不能把其他孩子的精彩动作自动归到目标人物名下。

已提供的上下文只有方案讨论。**没有证据表明 P0 已完成，没有现成代码、可运行服务、模型准确率或测试数据的确认结论。** 不要在交付报告中把设计目标写成已实现结果。

## 2. 目标、非目标与实施原则

### 首轮目标

跑通可用闭环：创建场次 → 导入视频 → 本地代理与索引 → 推荐候选事件 → 人工确认、裁切、补充与排序 → 从本地原片渲染横屏集锦 → 下载。

默认成片时长 30–60 秒，可调整；素材不足时允许生成更短视频，不能重复填充或虚构事件来凑时长。AI 暂时不可用时，人工新增片段、审核和渲染仍应可用。

### 非目标

- 第一版不做完整时间线视频编辑器、多人协作平台或云端素材管理。
- 不承诺全自动识别所有足球动作、可靠人脸识别、永久身份追踪或专业比赛战术分析。
- 不把 YOLO / ByteTrack 的检测或追踪结果直接当成足球事件判断。
- 不在首轮强求复杂 Remotion 包装、实时分析或可靠自动竖屏追踪裁切。
- 不自动发布到社交平台，不引入未经用户选择的背景音乐。

### 原则

1. 先建立端到端能力，再增强 AI、追踪、同步和包装。
2. 原始 4K 视频留在本地；远端模型仅在用户明确启用后接收选定的抽帧或短片段。
3. 事件判断、目标身份判断、双机位匹配分别记录置信度与证据。
4. 人工结果优先；重新分析不能覆盖已审核内容，重新渲染不能改变选片。
5. 采用本地单 Worker、串行重任务执行，避免多路 4K 解码争抢资源。
6. 不确定结果明确显示为疑似事件或身份不确定，不强行下结论。

## 4. 技术栈与结构建议

以下是默认建议，应结合现有仓库和 Mac mini 实际环境调整；不要为了统一技术栈重写已可用模块。

| 层级 | 建议 | 职责 |
|---|---|---|
| 前端 | React + Vite + Tailwind | 场次、素材、事件审核、导出设置 |
| 后端 | Python + FastAPI | API、校验、文件访问、任务管理 |
| 持久化 | SQLite + 迁移 | 场次、素材、候选、人工审核、导出、任务 |
| 执行 | 独立本地 Worker + SQLite 队列 | 串行执行重任务、失败恢复与重试 |
| 媒体处理 | FFmpeg / FFprobe | 元数据、代理、抽帧、片段预览与成片 |
| AI | 可配置多模态 API / 本地适配器 | 候选发现、验证、描述建议 |
| 追踪 | 可插拔 YOLO + ByteTrack | 人物位置与轨迹辅助，后续增强 |
| 包装 | 首轮 FFmpeg；后续评估 Remotion | 拼接、变速、字幕、简单效果 |

建议模块边界：`media`、`analysis`、`review`、`render`、`jobs`、`storage`。AI 供应商适配器应允许关闭、替换和使用明确标记的测试数据；演示结果不能混入真实识别结果。

建议本地目录：

```text
data/
  studio.sqlite
  sessions/<session_id>/
    originals/       # 本地原片或受控引用
    proxies/         # 浏览器播放代理
    thumbnails/
    frames/          # 分析缓存，可清理
    previews/        # 候选预览缓存
    exports/         # 成片与渲染清单
  logs/              # 不包含密钥或完整模型输入
```

上传导入默认保存原片副本；本机路径导入可作为后续选项。明确显示是否复制原片及预计磁盘占用，不移动或修改用户原文件。所有媒体路径由服务端根据 ID 解析，不接受任意文件路径访问。

## 5. 数据结构建议

时间统一使用源视频媒体时间秒数，保留足够精度；场次统一时间另行计算，不混用文件创建时间与视频时间。数据库 ID 使用稳定的 UUID 等标识。下列字段是建议，可按现有结构迁移。

| 实体 | 主要字段与约束 |
|---|---|
| Session | `id, title, training_date, notes, created_at, updated_at` |
| Asset | `id, session_id, device_type, original_path, original_filename, checksum, duration, width, height, fps, rotation, has_audio, captured_at, proxy_path, processing_status, error` |
| TargetReference | `id, session_id, asset_id, source_time, box_normalized, clothing_notes, local_reference_path`；由用户初始化目标人物 |
| AnalysisRun | `id, session_id, asset_id, provider, model, config_version, prompt_version, status, cost_estimate, actual_usage, created_at` |
| EventCandidate | `id, run_id, asset_id, start_s, end_s, event_type, event_confidence, identity_confidence, identity_status, evidence, suggested_description` |
| ReviewEvent | `id, session_id, candidate_id(nullable), asset_id, start_s, end_s, event_type, identity_status, decision, description, effects_json, version, created_at, updated_at` |
| SyncMapping | `id, session_id, asset_id, offset_s, drift_ratio, confidence, method, verification_status, anchor_pairs` |
| EventGroup | `id, session_id, match_confidence, status`；关联同一动作的不同机位事件，保留各自时间范围 |
| Export | `id, session_id, status, settings_json, review_snapshot_json, output_path, duration, error, created_at` |
| Job | `id, type, session_id, asset_id(nullable), state, phase, progress, attempts, max_attempts, heartbeat_at, cancel_requested, payload_json, error_code, error_message` |

枚举建议：

- `event_type`: `goal / shot / dribble / tackle / other`。
- `identity_status`: `confirmed_target / confirmed_other / uncertain`。AI 初步判断与人工确认要区分来源；模型输出不能自动标记成人工确认。
- `decision`: `pending / keep / discard`。
- `device_type`: `gopro / iphone / other`。

候选与审核数据分开保存：分析重跑新增 AnalysisRun 和候选；已审核 ReviewEvent 不覆盖、不删除。允许把新候选提示给用户进行合并。手工事件不依赖候选存在。导出保存审核快照与配置版本，防止渲染中修改审核影响当次输出。

效果设置可以包含 `slow_motion, speed, caption, focus_box, focus_time_range`。圈选与坐标采用归一化坐标，注明所对应的原片方向、时间和坐标系。

## 6. API 与任务状态建议

以下路径是建议，不代表已有实现。已有 API 可保持兼容。

| API | 行为 |
|---|---|
| `POST /api/sessions`、`GET /api/sessions` | 创建、列出场次 |
| `GET /api/sessions/{id}` | 场次、素材、任务摘要 |
| `POST /api/sessions/{id}/assets` | 流式上传导入；大文件方案按环境选择分片或可靠单文件上传 |
| `GET /api/assets/{id}` | 素材元数据、处理状态 |
| `GET /api/assets/{id}/media?variant=proxy` | 支持 Range 的受控媒体播放 |
| `POST /api/sessions/{id}/target-references` | 保存目标人物初始化 |
| `POST /api/assets/{id}/analyses` | 创建分析任务，返回 `202 + job_id` |
| `GET /api/sessions/{id}/candidates` | 分页查看候选与证据 |
| `POST /api/sessions/{id}/review-events` | 手工新增或从候选建立审核事件 |
| `PATCH /api/review-events/{id}` | 修改裁切、身份、类型、决定和效果；校验版本 |
| `PUT /api/sessions/{id}/timeline` | 保存所选事件顺序与机位选择 |
| `POST /api/sessions/{id}/sync` | 创建同步估计任务；另提供人工校准入口 |
| `POST /api/sessions/{id}/exports` | 校验选择，保存快照并排队渲染 |
| `GET /api/exports/{id}`、`GET /api/exports/{id}/download` | 导出状态、成功后下载 |
| `GET /api/jobs/{id}`、`POST /api/jobs/{id}/cancel`、`POST /api/jobs/{id}/retry` | 进度、取消、受控重试 |

约束：所有事件必须属于对应场次，满足 `0 <= start_s < end_s <= asset.duration`；导出只用明确保留的片段。重复点击通过幂等键或服务端去重避免重复分析收费、重复渲染。错误应返回用户可理解的信息以及可诊断的错误码。

任务状态：

```text
queued -> running -> succeeded
                  -> failed -> queued（显式或受控自动重试）
queued / running -> cancelled
```

`running` 细分阶段如 `probe / proxy / sample / analyze / verify / render / finalize`。未知耗时显示当前阶段与已处理媒体时间，不能编造进度。Worker 用事务原子领取任务并更新心跳；启动时识别失联任务，核查产物后恢复或标记为可重试。网络超时可限次退避重试，参数错误、预算不足不自动反复重试。

取消时终止受控子进程，保留原片与审核数据。临时成片成功校验后再原子移动到输出位置，失败文件不显示为成功导出。

## 7. P1：事件发现、身份判断、同步与去重

### P1-A：基础候选发现与验证

1. 对每个素材读取元数据、处理旋转信息并生成播放代理；用媒体时间索引抽帧。
2. 分别扫描 GoPro 与 iPhone 的完整时间范围。用重叠窗口覆盖窗口边界，避免动作被切断；窗口长度、抽帧频率与验证密度均可配置。
3. 首先产生低成本候选，再对候选前后更密集抽帧或生成短片验证。运动变化、场景变化、声音只能作为提示，不足以直接认定事件。
4. 模型按结构化格式输出时间范围、事件类型、事件置信度、身份置信度、证据与不确定原因。输出必须校验、限界，无法解析时记录失败或降级为待审。
5. 目标初始化由用户在清晰帧上框选孩子，可补充服装特征和多个参考帧。跟踪丢失、遮挡、相似服装时降低身份判断确定性。
6. 没有 AI 配置时提供手工流程，并明确显示“未运行 AI 分析”；不能用随机事件模拟实际结果。

事件口径初稿，实施前应形成可用于标注的规则：

| 类型 | 判定要求 |
|---|---|
| 进球 | 有足够证据支持球进入球门；远景看不清时标为疑似，不能仅凭庆祝认定 |
| 射门 | 能看到或合理追溯向球门方向的射门动作；结果不清楚时不补写进球 |
| 突破 | 带球绕过或摆脱防守并获得推进，避免把普通跑动都标为突破 |
| 抢断 | 对抗后使对方失去控制或己方获得球权；证据不足保留疑似 |

事件置信度高不代表是目标孩子；身份置信度高也不代表动作类型正确。模型数值暂作排序和审核提示，不解释为已校准概率，阈值需依据验证集调整。

### P1-B：同步、跨设备事件合并与追踪增强

- 文件拍摄时间只作为粗略起点；音频相关性、共同可见动作和人工锚点用于校准。
- 定义 `session_time = offset_s + source_time * drift_ratio`。短片可先使用固定偏移；长录制发现漂移时使用多锚点估计。
- 显示同步方法、置信度和人工确认状态。无有效音频或无法匹配时允许独立分析，不能强行对齐。
- 去重结合同步后的时间重叠、动作类型、人物与视觉证据，不能仅按时间接近自动删除。
- 同一动作建立 EventGroup，保留两个机位素材与源时间，用户选择更清晰机位或双机位切换。
- 同设备重叠窗口也需去重；保留来源和合并记录，支持撤销误合并。
- YOLO / ByteTrack 作为可插拔增强，先实测远景目标大小、轨迹稳定性和硬件耗时，再决定是否默认启用。

## 8. P2：人工审核台

桌面首轮布局：左侧视频预览、右侧候选与审核卡片、底部可定位的时间范围。手机先保证列表与基本审核可用，复杂拖拽以后优化。

必须支持：

- 播放候选前后上下文，跳转到原素材位置；显示机位、事件判断证据和两个独立置信度。
- 人工确认目标人物 / 其他人物 / 不确定，纠正事件标签和描述。
- 调整起止时间，提供数值输入和拖动两种方式；预览裁切范围，不能只改显示不保存。
- 保留、丢弃、待定；从任意原素材手工新增事件。
- 调整所选片段顺序；刷新后恢复身份、描述、裁切、选择与排序。
- 选择慢动作、字幕、简单人物圈选；P2-B 再扩展双机位切换与更多创意配置。
- 保存状态明确可见，保存失败能重试；使用版本校验避免旧请求覆盖新编辑。
- 重新分析后保留人工结果，新候选单独提示审核。

默认导出筛选目标身份已确认且被保留的事件；用户显式选择保留身份不确定事件时允许使用，但字幕不能断言是目标孩子。字幕以人工审核描述为准。

## 9. P3：FFmpeg 渲染引擎

### P3-A：首轮横屏成片

- 首先实现参数化“热血集锦”基础模板：事件顺序、简单片头、审核字幕、可选慢动作。
- 从本地原片按审核时间提取素材，统一方向、分辨率、帧率和音频参数后拼接。
- 横屏默认 `1920×1080`，`H.264 + AAC`；预设帧率结合源素材与设备性能确定，配置与导出快照记录一致。
- 无音轨素材生成静音轨保证拼接一致；处理 iPhone 旋转、可变帧率、不同画幅和音画同步。
- 慢动作只用于用户选择的范围；先明确原声变速或静音策略，不默认使用光流补帧。
- 字幕只取审核后的内容，验证中文字体、换行、转义、长文本与安全区域。
- 未配置音乐时只使用约定的原声策略；音乐仅来自用户提供且确认可用的本地素材，支持关闭。
- 渲染完成后用 FFprobe 校验时长、视频/音频流、尺寸与编码，并实际播放抽查关键接缝。

### P3-B：竖屏与视觉增强

- 竖屏 `1080×1920`。默认完整横屏画面加背景填充，避免丢失孩子、球与球门。
- 只有用户指定焦点或追踪经验证可靠时启用聚焦裁切，并允许预览与回退。
- 人物圈选必须绑定明确时间和位置；追踪不确定时使用短暂静态提示，不能把圈画到其他孩子身上。
- 增加训练日记、专业高光模板与双机位切换。复杂包装是否引入 Remotion 根据实际需求决定。

调用 FFmpeg 时使用参数数组，不把路径、字幕或用户输入拼成 shell 命令。临时目录按任务隔离；失败不污染已有成片。

## 10. 分阶段开发计划

| 阶段 | 任务 | 完成判据 |
|---|---|---|
| 0：现场审计 | 核查仓库与 P0，记录缺口，补齐必要基础 | 真实素材可导入、代理可播放、状态可恢复 |
| 1：人工闭环 | 数据迁移、审核事件 API、手工裁切与排序、基础横屏导出 | 不依赖 AI 即可制作并下载集锦 |
| 2：P1-A 接入 | 全素材扫描、结构化候选、验证、证据与独立置信度 | 真正分析的候选进入审核台，失败能处理 |
| 3：P2-A / P3-A 完整闭环 | 候选审核、效果、导出快照、任务恢复 | 导入→推荐→审核→横屏导出可复现 |
| 4：P1-B | 同步、去重、机位关联、追踪效果评估 | 已知双机位事件可关联，误合并可修正 |
| 5：P2-B / P3-B | 圈选、局部慢动作、双机位、竖屏、更多模板 | 各效果可预览，主体不可靠时能回退 |
| 6：评测与运行完善 | 标注评测、性能成本记录、说明与清理工具 | 有真实证据支撑验收及已知限制 |

每阶段交付可运行版本和验证记录。AI 识别未达到指标时继续保留人工闭环，并列出问题样本与改进方案；不要把未验证的能力包装成完成。

## 11. 测试与验收标准

### 功能验收

- 至少导入一段约 40 分钟 4K GoPro 素材及多个 iPhone 较长片段，记录设备、大小、时长、耗时和峰值资源使用。
- 刷新页面和重启服务后，场次、素材、任务状态、审核结果与排序保留。
- 中断 Worker、取消任务、模型超时、损坏视频、无音轨、磁盘不足均有明确失败信息，不丢原片或人工结果。
- 原片时间与代理时间能正确对应，裁切不会因旋转或可变帧率出现明显偏移。
- 有 AI 配置时扫描两种设备的完整时间范围；无 AI 配置时手工闭环可用。
- 重新分析不会覆盖人工确认，重复提交不会创建无控制的重复任务。
- 横屏成片规格、时长和音画同步正确，中文字幕能显示，下载文件实际可播放。
- 竖屏与视觉效果仅在阶段 5 完成后验收，不列为首轮已交付能力。

### 识别评测

建立本地人工标注测试集，包含远景、遮挡、相似服装、普通跑动、非高光 iPhone 片段及多种事件。标注事件时间范围、类别、参与者与可见证据。开发调参素材与独立验收素材分开，记录样本数和版本。

评测前固定事件匹配规则：以同一动作、同类别及约定时间容差或区间重叠阈值一对一匹配，重复候选不重复计为命中。初始阈值可讨论确定，但不能评测后为达标改口径。

- 事件召回率 = 正确找到的标注事件数 / 标注事件总数。
- 候选有效率 = 正确候选数 / 全部候选数；重复候选、误报按预先约定规则处理。
- **设计目标**：精彩事件召回率 ≥80%，候选有效率 ≥70%；这是目标，尚未验证。
- 分别报告总体、GoPro / iPhone、各类别、样本数量、漏检与误报，不用单个百分数隐藏小样本问题。
- 单独评估目标身份：错误归到目标孩子的次数、正确确认比例、不确定比例；不得把事件正确率当作身份正确率。
- 双设备同步报告标注锚点的时间误差，初始建议目标 ≤1 秒；去重单独报告正确关联与误合并，人工可修正。
- 证据不足的“疑似”单独统计；不能通过全部输出不确定绕过身份错误评测。

### 相称的自动检查

为时间范围校验、状态转换、重跑保留审核、同步映射、去重和导出快照写必要测试。媒体集成测试使用短小固定样本覆盖有/无音轨、旋转、不同帧率及中文路径。大型 4K 素材用于单独真实验收，不塞进每次单元测试。

前后端运行已有类型检查、构建与必要测试；只报告实际执行过的检查。检查通过后，除非出现新变更或疑点，不反复扩大测试。

## 12. 隐私、本地存储与成本约束

- 默认本地模式：原片、代理、目标参考、审核记录和导出都保存在本地，不默认上传云端或开启遥测。
- 远端 AI 默认关闭。设置页说明供应商、将发送的数据类型、抽样范围与预算；用户启用后才提交帧或短片，上传范围不能静默扩大到整段 4K 原片。
- 人物参考与儿童影像属于敏感素材，避免进入代码仓库、公共链接、错误日志或示例截图。密钥只从本地配置或环境读取，不写入数据库导出、前端或日志。
- 缓存按素材校验和、模型/提示/配置版本复用。先估算抽帧数量、调用数量和费用，配置场次预算上限与超限停止；价格以所选供应商实际配置为准，不编造固定费用。
- 显示原片、代理、分析缓存、导出所占空间；提供只清理可再生成缓存的工具。删除原片或整场数据必须是用户明确执行的操作。
- 默认绑定回环地址；手机局域网访问作为明确启用选项，配套访问口令或等效保护，不开放公网。
- 记录处理时间、调用用量与实际可得费用；记录硬件型号与内存，不能未经实测承诺实时处理或固定耗时。
- 不自动安装巨大的模型权重或购买服务；如确需新资源，先完成可运行的手工闭环，再说明具体选项与成本。
