# 产品定义

确认日期：2026-10-29。状态：用户已确认的产品范围；本文是实现与验收依据，不是已实现能力说明。

## 目标和边界

帮助用户找回日常对话中的做法、规则和沟通对象，包括谁在何时说过什么，并能回到原文和原音核对。

本产品负责录音、设备间传输、本地转写、声音身份管理、文字修订和知识库文件交付。每晚产出贴近原话的转写稿与清理后的阅读稿。知识提炼、采纳、冲突判断、Wiki 编译及问答由现有知识库 Agent 负责。

所有个人内容仅在 Watch、iPhone、Mac 与本地知识库之间处理。转写、声音匹配与文字清理不得调用第三方云端模型。模型及依赖的初次下载与个人内容处理分开。下游若使用云端 Agent，会改变这项本地边界，不能默认由本产品授权。

## 使用环境

- Apple Watch Series 10 GPS；iPhone 15 Pro。
- Mac：Apple M5、32 GB 内存；接受晚间批处理，不要求实时转写。
- 知识库：`/Users/raincai/Documents/ob_vault`；运行时路径应可配置。
- 主要语言：普通话，包含英文术语、人名、产品名和缩写。
- watchOS / iOS 版本、录音编码、切段长度、低电量阈值与耗电情况需实机验证后确定；不承诺连续 24 小时覆盖。

## 每天的操作

1. 用户在 Watch 启动一次当天录音，之后可暂停、继续、标记重点或停止。
2. App 自动保存多段文件。技术分段用于可靠存储与传输，不直接作为对话或知识库文档边界。
3. Watch 主要承担录音、状态显示和传输。低电量时保存当前片段、停止录音并提醒。
4. 来电、系统中断、低电量、存储不足等造成的缺口须可见；不得把缺口伪装成静音。
5. iPhone 接收并暂存录音。用户晚上打开手机 App，主动同步到 Mac。
6. Mac 完成本地处理，按连续对话拆分文档，交付到知识库 Inbox。无需用户每天回听或审核全部录音。

切段本身不能视为节电或降温措施。续航、发热、切段漏音和后台传输可靠性属于第一阶段实机验证项。

## 跨日补传与补交付

当天没有同步、Mac 不在线或传输失败时，未完成的数据继续保留。后续同步必须覆盖历史待传片段，不局限于“今天”。不因日期变化、App 重启或一次失败放弃待办。

两次设备交接分别确认：

- Watch → iPhone：手机校验并持久保存文件后才确认接收；此前 Watch 保留副本。
- iPhone → Mac：电脑校验并持久保存原音后才确认归档；此前手机保留副本。收到 Mac 归档确认后才允许按清理策略回收手机副本。

Mac 归档成功与知识库交付成功是两个独立状态。即使 Inbox 暂不可用，原音与处理结果仍在 Mac，待恢复后重试交付，不要求手机重传。

同步以稳定的片段 ID、大小和内容校验值核对。支持中断后补齐，已确认文件不重复归档。收到重复 ID 但内容不同时报告冲突，不覆盖原件。

分别记录：录音起止时间及其时区、Mac 接收时间、知识库交付时间。晚到数据保留真实发生时间；Inbox 按交付当天的摄入日期归档。

导出用持久记录追踪来源 ID、版本与交付结果。同一来源的同一版本只交付一次；下游已分流或移动文件后，不能因为原路径消失就重新投递。

补传数据在下一次本地批处理时补做转写和清理。批处理可重试，单段失败不阻断其他片段；待传、已归档、处理中、处理失败、待交付和已交付均可查看。

## 说话人标识流程

1. Mac 将一段录音中的不同声音分开，未知声音使用匿名编号，不阻塞文字交付。
2. 用户在电脑选择一段声音，回听样本，再选择已有姓名或创建新人物。
3. 人工标识的样本用于本地声音档案，后续录音尝试自动匹配；不确定时继续匿名或标为待确认。
4. 新标识会回填高把握的历史匹配。用户可以修改错误身份；人工确认优先于自动推断。
5. 不用未经确认的自动匹配反复强化声音档案。声音样本混入多人、重叠发言等情况要能纠正。
6. 历史姓名变化影响已导出的文档时，产生关联旧版本的修订交付，不直接改写知识库中的原件。

## 转写、清理与迭代

长期保留原音、原始转写和清理稿之间的来源关系，以及句段时间和说话人信息。用户日常阅读清理稿，核对时可切回原文和附近原音。

清理稿纠正专有名词、增加标点、去掉确无语义作用的填充词。保留否定、条件、程度、暂定语气、数字与单位，以及有强调或修正意义的重复；不得把提议改成决定，或补出未说过的内容。听不清时标注不确定，不编造补全。

文字支持按需修改。人工纠正人名和术语后，提供可编辑的个人词典用于后续处理；词典和修订记录持续累积。重新处理不得静默覆盖人工修订。

优先以词典、配置和已确认样本实现迭代；是否需要模型训练在实际错误积累后另行评估，不属于已承诺能力。

静音和无法辨认的声音可不生成文字，但保留时间范围和处理状态。可辨认的电视、视频或旁人谈话先保留，不在采集产品内判断其知识价值。

## 知识库交付契约

以实际读取的 `ob_vault/AGENTS.md`、`05 system/templates/tpl-inbox-capture.md` 及 `05 system/workflows/运行节奏与质量门槛.md` 为接入依据。接入实现时再次核对现行版本。

- 唯一入口：`00 Inbox/YYYY/MM/DD/`，日期按摄入时间。
- 以 Markdown 交付两版文字或两版文字的可访问关联，附完整录音起止时间、来源 ID、版本、说话人状态和原音定位。
- 使用现有 Inbox 元数据约定；录音专用的扩展字段在接入阶段固定，不自行改知识库规范。
- 来源身份未确认时明确标注；不以名字猜测人物身份。
- 不把原音和声纹作为 Markdown 内容或提交到 Git；原音在 Mac 的独立本机档案中长期保存。
- Inbox 的文字可继续修订，但本产品统一以版本交付；一旦被分流到不可变的 `00 raw/`，不覆盖或删除。修订版指明来源及前一版本，由知识库 Agent 处理后续关系。
- 不自动改 Wiki、运行知识提炼、提交 Git 或推送远端。

## 验收

用一周真实使用验证：白天采集，晚间同步，次日上午得到两版文字；用户挑选 10 条已知重要信息，至少 8 条能定位到正确原文，关键意思未改错。该指标验证素材质量与可定位性，不以本产品实现知识问答为前提。

声音匹配单独用人工标识的常见联系人验证，记录错误归人和未能匹配的样本，不预先声称准确率。

必须覆盖以下可靠性场景：

1. 连续多天不连接 Mac，之后一次同步补齐历史，并保留录音发生日期。
2. Watch 或 iPhone 传输中断、App 重启，之后补齐；接收前不清理唯一副本。
3. 同一批同步两次不重复入箱；文件已被知识库分流后也不重新投递。
4. Mac 已归档但 Inbox 写入失败，恢复后只补交付，不重复接收原音。
5. 原文件损坏或内容校验不一致时不确认成功，能够重试并显示失败。
6. 修改已导出的姓名或术语后，产生明确关联的修订版，不改不可变来源。
7. 低电量或系统中断后，已保存片段可用，缺口原因可见。
