# 分阶段实施计划

状态：待执行。产品范围见 [product-spec.md](product-spec.md)。阶段输出是计划，不代表已通过验证。

## P0：验证采集和传输

先在 Apple Watch Series 10 GPS、iPhone 15 Pro 上做最小录音与文件传输验证，避免在录音可靠性未知时投入知识库界面。

- 检查实际系统版本、完整 Xcode、设备配对和本机开发签名。已有环境检查只发现 Command Line Tools，尚未验证设备构建条件。
- 验证一次启动后的锁屏录音、自动切段、暂停/继续、标记和停止。
- 测量切段交界是否丢音、发热、耗电、来电或 Siri 中断后的状态。
- 实现 Watch 与手机持久队列、文件校验和接收确认。用断开连接及重启验证补传。
- 按测量结果确定编码、切段长度与低电量停止阈值。

通过标准：实机片段可回听，缺口可解释，断线后不丢未确认数据。模拟器或单元测试不能代替这项验收。

## P1：可靠送达 Mac

- 建立本地配对和加密传输，手机用户主动启动同步；传输协议实现前核对现行 Apple API 和后台限制。
- Mac 将原音存到源码仓库外，并维护片段来源、校验值、接收状态与确认记录。
- 支持历史待传、重复发送、传输中断、设备重启、校验失败和空间不足。
- 分开记录设备归档状态与下游交付状态，界面显示积压数量、最旧待传时间和失败原因。

通过标准：数日未同步后一次补齐，重复同步无重复原件，Mac 未成功归档前手机仍持有可重传副本。

## P2：本地转写与文字修订

- 用代表性中文及英文术语样本比较可在 M5 / 32 GB Mac 上运行的本地引擎，记录耗时和错误，不以模型宣传代替评估。
- 建立可重试批处理任务；保留音频、原始转写、清理稿与句段时间对应关系。
- 实现克制的口头词清理、术语词典、人工修订优先和版本记录。
- 合并跨技术文件的连续对话，再按对话拆分输出。分段策略在真实材料中调整，不把物理文件边界当成语义边界。

通过标准：次日上午产出两版文字；人工样本的否定、条件、数字及关键语义不被清理改变。

## P3：声音档案与历史回填

- 实现匿名说话人分段、电脑选段回听、姓名标注、已有姓名选择和纠错。
- 基于人工确认样本建立本地声音档案，跨录音匹配；低把握样本保持未知。
- 历史回填可重试，保留人工确认的优先级和身份修改记录；处理错误合并与多人混入样本。

通过标准：验证常见联系人在不同录音中的匹配与纠错，未知声音不阻塞转写和交付。

## P4：接入 ob_vault Inbox

- 再读现行 vault 规则，确定两版文字的 Markdown 排版、最小元数据、来源 ID、版本与原音定位方式。
- 以合成材料验证接入；真实原音和声纹保持在 Mac 独立档案目录。
- 实现持久导出记录和可重试写入，避免重跑、进程退出或下游文件移动造成重复。
- 晚到资料按当前摄入日期入箱，正文与元数据保留原始录音时间。
- 后续修订新增版本并标明关联，不修改已分流的 raw；知识提炼与 Wiki 更新维持现有责任边界。

通过标准：首次交付、重复执行、失败重试、跨日补交付和修订交付均能对账。

## P5：一周试用

按产品定义验收素材可定位性、关键语义、声音身份、续航、发热、漏录、同步积压与处理耗时。保留具体失败样本，以人工修正持续更新词典与声音档案。

每阶段只运行对应的定向测试。涉及录音、系统中断和设备间传输的结论必须标注实机验证情况；无实机证据时保留“未验证”状态。
